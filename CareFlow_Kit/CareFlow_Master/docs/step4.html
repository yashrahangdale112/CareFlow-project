STAGE 2 — Data cleaning aur feature engineering

python src/preprocess.py

Kya hota hai (yeh 7 kaam karta hai):

  1. Timestamp ko proper datetime me convert karta hai
  2. Duplicate events hatata hai (same case + activity + time)
  3. Blank resource ko UNASSIGNED se bharta hai
  4. Negative / ghalat numeric values ko 0 kar deta hai
  5. Bahut chhote (<3 events) ya bahut bade (>200 events) cases hata deta hai
  6. Features banata hai: waiting time, elapsed time, rework flag, shift, weekday, month
  7. Har case ka variant (activity sequence ki string) likh deta hai

STAGE 5 — Conformance checking (kitna deviate ho rahe hain)

python src/conformance.py

Kya hota hai: har patient ke journey ko discovered model se compare karta hai token-based replay se. Jo cheez model me allow nahi hai woh “deviation” ban jaati hai.

Fitness formula (report me likhiye):

fitness = 0.5 x (1 - missing / produced) + 0.5 x (1 - remaining / produced)
    produced  = actual me chalne wale steps
    consumed  = model ke hisaab se sahi steps
    missing   = model ke allowed transitions jo trace me nahi mile
    remaining = trace ke end me bache hue model tokens
{
  "model": "DFG (directly-follows graph)", "min_edge_count": 3,
  "cases_checked": 1500, "model_edges": 28,
  "average_fitness": 1.0,
  "perfectly_fitting_cases_pct": 100.0,
  "fully_conforming_cases_pct": 100.0,
  "cases_with_deviations": 0,
  "top_deviations": []
}
Honest interpretation (yeh viva me zaroor boliye): fitness 1.0 aaya kyunki yeh synthetic data hai jo fixed pathway templates se bana hai — jitni bhi rework loops hain, woh sab generator ke andar allowed hain, isliye model khud ke data ko 100 % explain kar leta hai. Asli hospital log par fitness generally 0.70 – 0.95 aata hai, aur top_deviations me “Lab Test → Discharge” jaisi skip-hop patterns dikhte hain. Yeh project ko kamzor nahi banata — methodology wahi hai, sirf data synthetic hai.

Output: conformance_report.json, conformance_by_variant.csv, conformance_fitness.png, deviation_types.png

STAGE 6 — Long-stay prediction model

python src/ml_model.py

Kya hota hai: 3 algorithms (Logistic Regression, Random Forest, Gradient Boosting) train hote hain, 2 feature sets par:

  • full — 19 features (sab kuch, including duration aggregates)
  • leakage_free — 14 features (duration-derived columns hata di, kyunki asli hospital me admission ke waqt waiting time pata nahi hota — isse “data leakage” kehte hain)
Data leakage kya hai? Agar aap model ko total_wait jaise columns doge jo outcome ke baad bante hain, to model 100 % accuracy dikha dega — lekin asli hospital me aise model ka koi fayda nahi. Isliye production model leakage-free features par banaya gaya. Yeh baat report aur presentation me likhne se aapka kaam professional lagta hai.
