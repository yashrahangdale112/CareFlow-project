1. Objective

Read a hospital event log and reconstruct the real clinical pathway; find bottlenecks, rework and deviations; predict long stays; and publish results as charts, reports and a dashboard — using industry-standard data-analytics workflow (collect → clean → validate → analyse → visualise → document).

2. Data model (process-mining event log)

One row = one event. Minimum columns: case_id (patient journey), activity (step), timestamp. Optional: resource, department, wait_minutes, service_minutes, cost_inr. Case-level attributes: age, gender, triage_level, admission_type, pathway, los_hours, total_cost_inr.

5. Methods

Process discovery: Directly-Follows Graph (DFG) + trace-variant analysis; optional Inductive / Heuristics / Alpha miner and token-based replay via pm4py. Conformance: token-based replay fitness per case and per variant, deviation typing. Analytics: KPI cards, bottleneck ranking by average wait, department cost, resource workload, weekday × hour heat map, LOS distribution. Predictive: binary classification of long stay (LOS > 24 h) with leakage-free features, 5-fold cross-validation, ROC-AUC / F1 comparison and confusion matrix.

8. Limitations

Reference log is synthetic (no patient-confidential data available); on real data expect lower fitness. Resource dimension is coarse. Cost is activity-level, not invoice-level. Long-stay class is highly imbalanced (1.13 %), so accuracy is a misleading metric — AUC, recall and F1 are reported instead.
