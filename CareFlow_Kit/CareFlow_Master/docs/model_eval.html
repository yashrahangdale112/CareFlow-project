2.2 Leakage-free feature set — 14 features

Five duration-derived columns are removed: total_wait, avg_wait, max_wait, total_service, wait_ratio.

Why remove them? These columns are computed from the timestamps of the same journey whose length is the prediction target. In a real hospital, the long-stay decision must be taken at admission, when no waiting time or service duration has yet occurred. Including them therefore produces an academically perfect but operationally useless model — a textbook case of target leakage. The leakage-free set (11 numeric + 3 binary/derived + 5 categorical) is what the deployment model actually uses.

5. Interpretation of the leakage comparison

ObservationExplanation
Full feature set scores a perfect 1.000 on every metricIt contains waiting-time and service-time aggregates derived from the same timestamps that define length of stay — the target is effectively an arithmetic function of the inputs
Cross-validated F1 also 1.000 for the tree ensemblesThe leakage is structural, not a lucky split, so it survives resampling
Logistic Regression full-set CV F1 is only 0.727A linear boundary cannot combine the leaky columns as cleanly; it shows the leakage is interaction-driven
Removing 5 columns drops accuracy by only 0.33 ppThe genuinely predictive signal lives in structural, admission-time features
ROC-AUC stays at 0.998 after removalRanking ability is preserved — the model still separates risk correctly
Random Forest F1 collapses to 0.000At a 3-positive test set, an ensemble that predicts "no" for everything still scores 0.990 accuracy — which is exactly why F1, not accuracy, was used for selection

7. Uncertainty and honest limitations

  • The test set contains only 3 positive cases. One additional miss would drop recall from 0.667 to 0.333 and F1 from 0.800 to 0.500. These metrics are indicative, not precise.
  • Cross-validated F1 for the production model is 0.180 ± 0.223 — high variance driven by folds that contain very few positives. Accuracy and ROC-AUC remain stable.
  • All data is synthetic. Real hospital data has messier feature distributions, missing values and drift; expect lower absolute performance.
  • Long-stay cases (1.13 %) were not artificially oversampled or rescaled. SMOTE or class-weight balancing would be the next experiment.
  • The model is explanatory at the operational level and is not a clinical decision tool.

8. Recommended next experiments

  1. Apply class_weight='balanced' and SMOTE oversampling; re-measure F1 and recall.
  2. Replace the binary target with regression on los_hours and report MAE/RMSE.
  3. Tune the decision threshold via a precision–recall curve instead of using 0.5.
  4. Add SHAP values for per-patient explanation.
  5. Re-train on a real hospital log and compare against the synthetic baseline in this report.
  6. Introduce time-based (rolling) validation to simulate production deployment.
